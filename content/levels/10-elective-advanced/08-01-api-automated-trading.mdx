## 한 줄로

API 자동매매는 매매 규칙을 코드로 구현해 감정 개입 없이 일관되게 실행하는 시스템이며, 백테스트 → 종이매매 → 소액 실전의 단계적 검증과 기술적 장애 대비가 필수다.

## 왜 알아야 하나

Level 8에서 감정이 매매를 어떻게 방해하는지 배웠고, Level 9에서 규칙 준수의 중요성을 강조했다. 자동매매는 이 문제의 궁극적 해결책이다. 코드는 FOMO에 빠지지 않고, 복수매매를 하지 않으며, 일일 손실 한도에 도달하면 확실히 멈춘다.

## 개념

**자동매매 시스템의 구성 요소:**

1. 데이터 수집: 실시간 시세, 호가, 체결 데이터 수신
2. 시그널 엔진: 전략 로직에 따라 매수/매도 신호 생성
3. 주문 실행: 증권사 API를 통한 주문 전송
4. 리스크 관리: 포지션 크기 제한, 일일 손실 한도, 비상 정지
5. 모니터링: 시스템 상태, 포지션, 손익 실시간 감시
6. 로깅: 모든 판단과 주문의 상세 기록

**단계적 구축 로드맵:**

1단계: API 기초 — 계좌 조회, 시세 조회 (2주)
2단계: 주문 전송 — 매수/매도/취소 (2주)
3단계: 간단한 전략 자동화 — 이동평균 크로스 (2주)
4단계: 리스크 관리 모듈 — 손절, 일일 한도 (2주)
5단계: 종이매매 테스트 (1~3개월)
6단계: 소액 실전 (1~3개월)
7단계: 정상 규모 (검증 완료 후)

**필수 안전 장치:**

1. 킬 스위치: 비상 시 모든 포지션을 청산하는 버튼/명령어
2. 일일 손실 한도: 한도 도달 시 자동으로 매매 중단
3. 최대 포지션 한도: 1종목 최대 비중, 총 포지션 한도
4. 장애 대응: 네트워크 끊김 시 포지션 유지/청산 정책
5. 알림 시스템: 이상 상황 발생 시 SMS/메신저 알림

**기술 스택 (한국 시장):**

- 언어: 파이썬 (가장 많은 라이브러리 지원)
- API: 한국투자증권 OpenAPI, 키움 OpenAPI+
- 서버: 클라우드(AWS/GCP) 또는 로컬 PC
- 데이터베이스: SQLite (소규모), PostgreSQL (대규모)

## 비유로 이해하기

자동매매는 자율주행과 비슷하다. 규칙을 코드로 구현하고, 센서(시세 데이터)를 통해 판단하며, 액추에이터(주문 API)로 실행한다. 자율주행처럼, 충분한 테스트 없이 도로에 나가면 사고가 난다.

## 실제 시장에서는

2012년 나이트 캐피탈 그룹(Knight Capital Group)은 소프트웨어 배포 오류로 45분 만에 4억 4,000만 달러를 잃었다. 자동매매 시스템이 의도하지 않은 대량 주문을 실행한 것이다. 이 사건은 자동매매의 테스트·배포 프로세스와 킬 스위치의 중요성을 보여주는 교과서적 사례다.

## 흔한 오해

**"자동매매를 만들면 신경 쓸 것이 없다."** 시스템은 지속적 모니터링, 유지보수, 업데이트가 필요하다. API 변경, 시장 구조 변화, 전략 부진 등에 대응해야 하며, "만들고 놔두면 끝"이 아니다.

**"자동매매는 항상 수동매매보다 좋다."** 자동매매의 장점은 일관성이지, 수익성이 아니다. 나쁜 전략을 자동화하면 나쁜 결과를 일관되게 만들 뿐이다. 전략의 기대값이 먼저이고, 자동화는 그 다음이다.

**시작하기 전 체크리스트:**

자동매매에 진입하기 전에 확인해야 할 것이 있다. ① 수동매매로 최소 6개월 이상 규칙 기반 매매를 실행한 경험이 있는가? ② 자동화할 전략의 백테스트 결과가 충분한가(6-4)? ③ 파이썬 기초(10-1)와 API 통신의 기본 개념을 이해하는가? 이 세 가지가 갖춰지지 않은 상태에서 자동매매를 시도하면, 코드의 버그와 전략의 문제를 구분할 수 없어 양쪽 모두 개선이 어렵다.
